Interactive teaching improvements
=================================
Maintainer notes, started 2026-10-19. This file is not a website chapter.
Keep it out of docs/ and the site search index. It is visible in the source
repository; do not put private student information here.

Approach
--------
Preserve the existing explanations, diagrams, and Arduino examples. Add one
or two small, focused demonstrations per batch at the point where a lecturer
would use them. Each should answer a concrete question, have sensible defaults,
labelled controls and units, reset, and a short classroom prompt. Prefer local
HTML/CSS/JavaScript with no accounts, server, or external runtime dependency.
Use SVG for plots. Check the maths, endpoints, keyboard use, mobile layout,
and enlarged classroom view before publishing. Explain idealisations beside
the demo; do not imply that simulated values are calibrated measurements.

[verified] ADC explorer: input voltage and bit depth, code, binary bit
weights, quantisation staircase, and width of the current code's interval.
Start with 3 bits, then compare with 12. Show why 4096 values end at code 4095.
Ideal model: 2^N equal bins across 0-3.3 V, floor(Vin/LSB), clipped at full scale.
This deliberately distinguishes bin width (3.3/4096 at 12 bits) from the
existing sketch's approximate endpoint conversion (code * 3.3/4095).
ESP32 hardware range depends on chip and attenuation; more bits do not remove
noise. Resolution settings below the hardware range are a teaching model.

[verified] PWM explorer: duty cycle, frequency, fixed time window or
two-period view, pulse waveform, time-average voltage, period, and HIGH time.
Include 0% and 100% endpoints. The pin switches between voltage levels; its
time average is not a steady intermediate output voltage.

Batch 2: RGB and deep sleep
--------------------------
[verified] RGB mixer — tutorials/RGB.qmd
    Three 0-255 sliders, colour swatch, decimal RGB and hexadecimal values,
    and presets. Keep the current LED example. Explain that screen colours
    and a physical addressable LED do not have identical brightness/gamma.
    Teaching question: which channels make yellow, cyan, and white?

[verified] Battery-life calculator — tutorials/deep_sleep.qmd
    Active/sleep current, duration, and usable battery capacity; show weighted
    average current, estimated runtime, and contributions to energy use.
    Make mA vs microamp units explicit. Use editable, labelled example values,
    not a claimed FireBeetle measurement. Include sensors, regulators and
    wake-up work; model is an estimate, not a battery discharge simulation.
    Teaching question: does a shorter wake time or lower sleep current help
    more for this duty cycle?

Includes: _includes/rgb-demo.qmd, _includes/sleep-demo.qmd
Assets: assets/rgb-sleep-demos.js, assets/rgb-sleep-demos.css, plus the existing
assets/teaching-demos.css. These demos do not change the ADC/PWM assets.
RGB includes eight presets, a colour swatch, an additive mixing diagram,
decimal and hex readouts, and a snippet using the existing strip object.
The physical LED also depends on its brightness setting and colour response;
the preview displays RGB values directly rather than modelling LED hardware.

The battery model uses average TOTAL BATTERY-SIDE current in each state,
not bare-chip current or 3.3 V rail current mixed with battery-rated mAh.
Sleep time is additional to awake time. Usable capacity is an editable
fraction of nominal capacity. Regulator/sensor current and wake-up work must
be included in the measured inputs. Self-discharge, temperature and changing
battery voltage are not modelled, so long runtime estimates are optimistic.
Compare time fraction with charge fraction; at the defaults, 3.3% awake time
accounts for 98.2% of charge used. No-sleep and 1-/5-minute timing presets.

Two short corrections beside the calculator: board components also draw
current; RTC-retained variables survive deep sleep, while ordinary RAM and
peripheral state do not, and wake-up restarts the application.
Reference: https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/sleep_modes.html
Library: https://github.com/Freenove/Freenove_WS2812_Lib_for_ESP32

Cross-page and content notes
----------------------------
- tutorials/electronics-class-old.qmd and archive/teaching-material/
  electronics-class.pdf repeat ADC/PWM concepts. Put new demos in the current
  lecture first; later link from the older page instead of duplicating them.
- The old presentation also discusses ADS1115. Its signed 16-bit codes and
  programmable input ranges need their own model, not an unsigned 16-bit
  extension of the ESP32 demonstration.
- ADC/PWM explanations also occur in digital-read-write.qmd and control.qmd.
  Reuse includes/assets or cross-link so fixes do not diverge between copies.
- archive/code/potentiometer-PWM.ino uses legacy ledcSetup/ledcAttachPin.
  Review Arduino-ESP32 version assumptions in a separate code-update batch;
  the current API uses ledcAttach and pin-based ledcWrite.
- Installation, IDE, library and board setup pages primarily need version
  checks, not interactive decoration. Breadboard, relay and sensor wiring
  may later benefit from annotations, but preserve real wiring photographs.
- Browser verification found an existing polyfill.io request failing in the
  old page template. The new demos have no external runtime dependencies and
  still initialise correctly. Review that old template dependency as part
  of a future site-wide build/tooling update.

Reference checks for current batch
----------------------------------
https://docs.espressif.com/projects/arduino-esp32/en/latest/api/adc.html
https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html
ADC defaults to 12-bit (0-4095); analogRead is raw and analogReadMilliVolts
provides calibrated millivolts. Actual measurable range depends on hardware
and attenuation. PWM frequency and hardware duty resolution are related;
the present demo illustrates the waveform rather than LEDC configuration.
