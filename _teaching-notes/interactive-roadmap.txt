Interactive teaching improvements
=================================
Maintainer notes, started 2026-10-19. This file is not a website chapter.
Keep it out of docs/ and the site search index. It is visible in the source
repository; do not put private student information here.

Approach
--------
Preserve the existing explanations, diagrams, and Arduino examples. Add one
or two small, focused demonstrations per batch at the point where a lecturer
would use them. Each should answer a concrete question, have sensible defaults,
labelled controls and units, reset, and a short classroom prompt. Prefer local
HTML/CSS/JavaScript with no accounts, server, or external runtime dependency.
Use SVG for plots. Check the maths, endpoints, keyboard use, mobile layout,
and enlarged classroom view before publishing. Explain idealisations beside
the demo; do not imply that simulated values are calibrated measurements.

[verified] ADC explorer: input voltage and bit depth, code, binary bit
weights, quantisation staircase, and width of the current code's interval.
Start with 3 bits, then compare with 12. Show why 4096 values end at code 4095.
Ideal model: 2^N equal bins across 0-3.3 V, floor(Vin/LSB), clipped at full scale.
This deliberately distinguishes bin width (3.3/4096 at 12 bits) from the
existing sketch's approximate endpoint conversion (code * 3.3/4095).
ESP32 hardware range depends on chip and attenuation; more bits do not remove
noise. Resolution settings below the hardware range are a teaching model.

[verified] PWM explorer: duty cycle, frequency, fixed time window or
two-period view, pulse waveform, time-average voltage, period, and HIGH time.
Include 0% and 100% endpoints. The pin switches between voltage levels; its
time average is not a steady intermediate output voltage.

--------------------------
[verified] RGB mixer — tutorials/RGB.qmd

[verified] Battery-life calculator — tutorials/deep_sleep.qmd
    Active/sleep current, duration, and usable battery capacity; show weighted
    average current, estimated runtime, and contributions to energy use.
    Make mA vs microamp units explicit. Use editable, labelled example values,
    not a claimed FireBeetle measurement. Include sensors, regulators and
    wake-up work; model is an estimate, not a battery discharge simulation.
    Teaching question: does a shorter wake time or lower sleep current help
    more for this duty cycle?

Includes: _includes/rgb-demo.qmd, _includes/sleep-demo.qmd
Assets: assets/rgb-sleep-demos.js, assets/rgb-sleep-demos.css, plus the existing
assets/teaching-demos.css. These demos do not change the ADC/PWM assets.
RGB includes eight presets, a colour swatch, an additive mixing diagram,
decimal and hex readouts, and a snippet using the existing strip object.
The physical LED also depends on its brightness setting and colour response;
the preview displays RGB values directly rather than modelling LED hardware.

The battery model uses average TOTAL BATTERY-SIDE current in each state,
not bare-chip current or 3.3 V rail current mixed with battery-rated mAh.
Sleep time is additional to awake time. Usable capacity is an editable
fraction of nominal capacity. Regulator/sensor current and wake-up work must
be included in the measured inputs. Self-discharge, temperature and changing
battery voltage are not modelled, so long runtime estimates are optimistic.
Compare time fraction with charge fraction; at the defaults, 3.3% awake time
accounts for 98.2% of charge used. No-sleep and 1-/5-minute timing presets.

Two short corrections beside the calculator: board components also draw
current; RTC-retained variables survive deep sleep, while ordinary RAM and
peripheral state do not, and wake-up restarts the application.
Reference: https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/sleep_modes.html
Library: https://github.com/Freenove/Freenove_WS2812_Lib_for_ESP32

The resistor explorer starts with a resistor-only circuit; LED mode subtracts

power are not calculated at R = 0. LED current limits and resistor power
ratings are editable examples, not universal component or GPIO ratings.

[verified] Breadboard explorer — tutorials/breadboard.qmd
    Prioritised at the user's request. Click a hole to reveal its connected
    group; add/remove jumper wires; test two holes for continuity. Show the

Include: _includes/breadboard-demo.qmd
Assets: assets/breadboard-demo.js and assets/breadboard-demo.css, plus the

The shortened board has 10 numbered rows, two five-hole terminal strips per
row and four side rails. In split mode, each rail has two groups of five;
in continuous mode each rail has ten connected holes. Actual boards vary.
Connectivity is a graph of metal strips and jumper endpoints. Wire crossings
and passing over intermediate holes never create connections. Each hole can
hold one jumper endpoint; up to 12 jumpers keep examples manageable. Same-strip
jumpers are allowed and explain why they add no new connection. This is a
connectivity model without power sources, component or current simulation.

Keyboard: one tab stop among the holes, arrow navigation and Enter/Space to
choose; Escape or a button cancels a pending endpoint. All hole names, attached
jumpers, selection and probes have accessible labels. Continuity results are
announced. Small screens scroll the board locally to retain usable targets.
Controls appear before the board in the page and beside it when enlarged.

Calibration assumes a linear sensor response. Coefficients are calculated
from the actual distance between reference codes, not from ADC full scale.
Duplicate codes give an undefined result; equal reference angles give a flat
line with an explanation. Out-of-interval estimates are not clamped. Graph
rescales vertically; displayed coefficients are rounded but computation uses
full precision. Defaults are illustrative, not measured board calibration.
Reference: https://learn.adafruit.com/calibrating-sensors/two-point-calibration

The fan demo accepts temperature readings without simulating room cooling.
ON when T >= the ON setting; OFF when T <= the OFF setting; otherwise retain
state. If settings are equal, ON wins at equality; OFF below. Integer tenths
keep comparisons exact. OFF cannot exceed ON; input limits stay synchronized.
Changing settings or clearing the graph starts a new history: initially OFF
unless the current reading reaches ON. Keep the last 48 readings; x-axis is
reading number, not seconds. ON means fan operation, not a GPIO level; the
existing relay discussion remains relevant. The original behavior reference
was https://www.ti.com/lit/ds/symlink/tmp709.pdf, sections 7.3.1-2 and 8.2.3.
This is an illustrative software controller, not an emulation of that device.

Completed batch 6: pulse counting and MQTT topics
------------------------------------------------
[verified] Pulse counting — tutorials/pulse-sensors.qmd
    Sliders for pulses per second and counting duration; editable pulses per
    litre. Show whole pulse count, measured pulses/s, flow in L/min and the
    effect of one extra pulse. Waveform marks each counted LOW-to-HIGH jump.
    Evenly spaced pulses at t = n/f, n >= 1, counting 0 < t <= duration;
    N = floor(f * duration), measured frequency = N / duration,
    volume = N / pulses-per-litre, flow = volume * 60 / duration.
    First rising edge is after one complete interval. No thermal or fluid
    dynamics, sensor calibration or physical timing is implied. Defaults are
    illustrative, and the explanation states that a different starting point
    in a real signal can change the count by one. Controls update immediately.
    Source headings now match the published subheading levels so navigation
    and numbering remain consistent. Existing Arduino programs unchanged.

[verified] MQTT topics — tutorials/MQTT.qmd
    Local sender, broker explanation and three editable screens. Preview
    matching subscriptions before Send; afterwards show who received the
    message, latest text and counts. Other screens keep their previous text;
    changing a screen's subscription clears its received messages. Reset all.
    Exact matches, + for one level, # at the end for zero or more levels;
    support empty levels, case/space sensitivity, and the special rule that
    initial +/# does not match a leading $. Validate topic/filter syntax,
    reject null/unpaired surrogates, limit topic fields to 160 UTF-16 units
    for this demo. Render message contents as text, including empty payloads.
    No broker connection, storage, delivery retries, retained messages,
    sessions or packet transport. Not a complete MQTT implementation.
    Corrected the existing "single level ... followed by another level"
    sentence to say two parts, and fixed "calss" beside the broker link.

[verified] I2C addresses — tutorials/digital-sensors.qmd
    Two SHT31s and one VL53L0X share SDA/SCL. Choose the two SHT31 hardware
    addresses (0x44/0x45), connect/disconnect sensors, ask one address or scan.
    Unique reply gives a labelled example reading; no reply and duplicate
    addresses have explicit text. The scan lists unique addresses and cannot
    reveal multiple devices at one address. A duplicate elsewhere does not
    prevent a request to a different, unique address. Configuration edits
    clear prior replies/scans; changing only the target preserves the scan.
    Diagram shows separate SDA/SCL lines, junction dots and non-junction
    crossings. It omits power/ground/pull-up components, stated beside it.
    This is an address-selection model, not electrical timing or packet
    emulation. Sensor libraries are still needed to request measurements.
    VL53L0X stays at the library default 0x29; real software address changes
    and multiple VL53L0X startup are outside this demo. SHT31 selections
    represent ADDR hardware settings, not arbitrary software configuration.

[verified] Saving interval — tutorials/cloud-connectivity.qmd
    Save every 1-60 seconds, first reading 0 to interval-1 seconds. A fixed
    five-minute example has temperature 24 + 10*max(0,1-|t-150|/15), in °C.
    Save exactly at start + n*interval, including 300s when it lands there.
    Compare the continuous example curve with saved points and their joined
    line. Counts and highest saved temperature update immediately. Changing
    interval clamps start to a valid value; one-second interval fixes start
    at zero. Show partial or complete missed warming in plain language.
    The diagram's straight connecting lines are not additional measurements.
    Values are illustrative; no network request, persistent storage or real
    ThingSpeak upload is made. Link to official service update limits instead
    of claiming all displayed intervals are allowed on every account.
